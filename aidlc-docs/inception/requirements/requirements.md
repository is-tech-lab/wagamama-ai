# Requirements - わがママAI

## Intent Analysis Summary

| 項目 | 内容 |
|------|------|
| リクエストタイプ | New Project（Greenfield） |
| スコープ | System-wide（モバイルアプリ・複数AWSサービス・スマート家電連携） |
| 複雑度 | Complex |
| プロジェクト目標 | ハッカソン用だが、そのままプロダクションに昇格させたい |

---

## コンセプト

「わがまま（自分の欲求に正直）」×「お節介なお母さん」。
ユーザーが言わなくても先回りして動き、時にはうるさいくらい世話を焼いてくれるAIアシスタント。

---

## 機能要件

### 1. コーディネート提案（天気・予定の先回り含む）
- ユーザーのスマホデータ（購買履歴、カレンダー等）から好みを自動学習する
- 毎朝、その日の予定・天気・状況に合わせた服装をAIが提案する
- 雨予報の日は「傘持って行きなさい」と一言添えて通知する
- 気温差が大きい日は重ね着を提案するなど、体調管理の観点も含める
- チャット形式でユーザーに提案を通知する

### 2. 料理手配・健康おせっかい（Uber Eats連携）
- ユーザーのカレンダー・健康データ・位置情報を元に食事内容を提案する
- 食事履歴から栄養バランスを分析し、「最近野菜食べてないでしょ」と野菜多めの料理を勝手に提案する
- Uber Eats等の外部サービスAPIと連携して自動注文する
- ユーザー承認後に発注する

### 3. プレゼント選定・発注
- 友人・恋人のカレンダー（誕生日・記念日）を検知する
- 相手の欲しい物リストをデータソースとして活用する
- AIが候補を選定 → ユーザーが承認 → 自動発注する
- しばらく連絡していない友人を検知して「〇〇ちゃんに連絡しなさい」と促す

### 4. 起床サポート
- スマホのネイティブアラームと同期する
- カレンダーの予定を考慮した起床サポートを行う（将来拡張）

### 5. スマート家電連携（家事サポート）
- Nature Remo等のスマート家電サービスのAPIと連携する
- 洗濯機・掃除ロボット等の家事を状況に応じて自動手配する

### 6. 財布の管理（節約おせっかい）
- 購買履歴から月の支出を分析する
- 使いすぎを検知したら「今月使いすぎ！」と警告し、節約メニュー・代替案を提案する

### 7. 締め切り・タスク催促
- カレンダーの締め切り・重要予定を検知する
- 締め切りが近づくと「ちゃんとやってる？」と定期的に進捗を催促する

### 8. 帰宅確認
- 位置情報を監視し、夜遅くまで外にいる場合「早く帰りなさい」と通知する
- 帰宅を確認すると安堵のメッセージを送る

### 9. 美容院・身だしなみ管理
- 前回の美容院来店から一定期間が経過すると、自動で美容院を予約する（将来拡張）
- その他、定期的なメンテナンス（歯医者等）のリマインドも行う（将来拡張）

### 10. 就寝催促
- 深夜にスマホを使用していることを検知すると「もう寝なさい！」と通知する
- 翌日の予定が早い場合は早めに就寝を促す

### 11. スマホ情報の統合読み取り
- カレンダー（予定・スケジュール）
- 位置情報
- 購買履歴
- ヘルスデータ（睡眠・運動・食事）
- 上記すべてを統合し、ユーザーの状況を理解・先回り行動する

### 12. パーソナライズ・学習
- スマホデータから自動的にユーザーの好みを学習・蓄積する
- 学習内容は継続的に更新される

### 13. 通知・インタラクション
- チャット形式（LINE・Slack風）でユーザーにメッセージを送る
- 将来的に音声（テキスト読み上げ）への拡張を想定する

## 非機能要件

### フロントエンド
- スマホアプリ（iOS / Android）
- ネイティブアラーム・プッシュ通知と連携できること

### バックエンド
- 実装言語: TypeScript / Node.js
- フレームワーク: Hono
- 後からスマホデータ自動学習へ拡張できるアーキテクチャ

### インフラ
- クラウド: AWS
- リージョン: ap-northeast-1（東京）
- IaCツール: AWS CDK（TypeScript）

### セキュリティ
- Security Baseline Extension 適用（本番グレード、すべてのSECURITYルールをブロッキング制約として適用）
- スマホデータへのアクセスには適切な権限管理・暗号化を行う

### テスト
- Property-Based Testing (PBT) Extension 適用（すべてのPBTルールをブロッキング制約として適用）

### 拡張性
- 各機能は独立したモジュールとして設計し、個別に拡張・差し替えができること
- 外部API連携（Uber Eats、Nature Remo等）は疎結合に保つこと
